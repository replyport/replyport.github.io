Privacy policy

ReplyPort is a Windows desktop utility by Sergey Alexeev for user-authorized Outlook Classic workflows and AI-assisted analysis and drafting. This proposed update also describes the optional ReplyPort-operated Cloudflare MCP service.

Overview

What ReplyPort does

ReplyPort works locally with Outlook Classic. You select which Outlook mailboxes and folders to copy into ReplyPort’s dedicated App Folder in your own Dropbox. An AI assistant or other tool that you separately authorize can use those copies to help search, analyse and prepare a reply. ReplyPort creates the resulting draft in the correct Outlook account.

Draft only. ReplyPort does not automatically send email. It does not send mail through SMTP, Microsoft Graph or another cloud mail transport. The user must review every generated draft and manually decide whether to send it in Outlook.

The Windows application does not provide a hosted AI model or a mail-sending service. It works with Outlook Classic and Dropbox; any external AI service or integration must be connected and authorized separately.

Owner and legal review required before publication. The hosted-service data flow, OAuth-grant cleanup, Dropbox draft-record expiry, and Cloudflare platform-level retention need owner confirmation. The service has not passed its customer rollout gates and is not verified as a live ChatGPT or Claude directory listing.

Information

Personal information accessed and why

ReplyPort accesses the following information only as needed for functions the user authorizes. Mailbox and folder selection, and optional attachment copying, are controlled locally on the user’s PC:

  • Outlook message content and metadata: message body text, subject, sender and recipient details, date, conversation information, message identifiers, sensitivity or protection state, and attachment metadata. This supports approved export, search, analysis, triage, reply drafting, threading and safety checks.
  • Email attachment contents, only if the user turns this on: the files attached to messages ReplyPort has already copied, for mailboxes where the user has chosen to copy email attachments. This lets an AI tool the user connects to that Dropbox folder read those attachments with their email.
  • Outlook account and routing information: the configured account address, Outlook profile, store and folder information, approved signature information and local Outlook item locators. This lets ReplyPort keep work within the correct mailbox, preserve Outlook's recipients and conversation, and place the draft in the correct Drafts folder.
  • Operational information: configuration, opaque identifiers, capability material, hashes, indexes, checkpoints, journals, status, error codes and bounded work counts. This supports security, integrity, recovery, deduplication and diagnostics.

Copying email attachments is an optional setting for each mailbox, shown in ReplyPort as Include email attachments. It is off by default, can be turned on only for a mailbox whose mail copying is on, and can be turned on only by the user on their PC. When it is on, ReplyPort copies supported attachment types (documents, spreadsheets, presentations, text files and images) within size limits, from messages it has already copied, into the ReplyPort folder in the user’s Dropbox. Other attachments are not copied and remain in Outlook. Turning the setting off stops copying and removes the attachment copies ReplyPort made. ReplyPort refuses protected or incomplete message content for drafting. The Windows application does not use Outlook email content for advertising, and the publisher does not sell that content.

Storage and protection

Where information is stored

Dropbox storage

In the current consumer release, Dropbox is required; no other storage provider is supported. ReplyPort requires Dropbox Desktop signed in on the same Windows PC. It stores selected email snapshots and metadata, optional approved attachment copies, and AI work records inside the dedicated ReplyPort Dropbox App Folder, under Dropbox/Apps/ReplyPort (or a Dropbox-assigned name such as ReplyPort (1)). It does not use a separate /ReplyPort folder at the top level of Dropbox. The Windows worker reads and writes the synchronized local App Folder rather than storing a separate mailbox corpus elsewhere on the PC.

During connection and verification, ReplyPort uses Dropbox authorization and the Dropbox API to identify the selected account and dedicated App Folder and to write/read small synchronization-verification files. The Windows worker uses the local Dropbox Desktop copy for ongoing mailbox mirroring and draft requests. Dropbox Desktop synchronizes those copies with the user’s Dropbox account, so Dropbox processes the files under its own terms and privacy policy. The Dropbox API permission granted directly to ReplyPort is restricted to its App Folder, plus basic account information; it does not give that app API access to unrelated Dropbox files. The App Folder must be available locally for ReplyPort to verify it before setup can continue.

Local operational state

ReplyPort keeps operational state under the current user’s local Windows profile. This includes configuration, protected Dropbox App Folder identity and Outlook routing state, DPAPI-protected capability keys and journals, hashes, indexes, checkpoints, retry state and content-free logs. The desktop Dropbox authorization is held in memory for setup and revalidation, not stored as a permanent worker credential. Local logs record operational identifiers, states, durations, error codes and bounded counts rather than email subjects, bodies, senders, recipients or attachment filenames.

Safeguards

ReplyPort uses the current Windows user’s filesystem permissions, Windows Data Protection API protection for local secrets and sensitive operational state, verified Dropbox App Folder account and namespace binding, opaque mailbox identifiers, mailbox-scoped capabilities, immutable records, and strict Outlook routing and draft verification. Per-mailbox directories inside the App Folder provide logical separation, not independent Dropbox access controls. Dropbox’s App Folder API restriction applies to ReplyPort’s own Dropbox app authorization; a separately connected AI tool may receive different Dropbox permissions. Users should review each connection and secure their Windows, Outlook, Dropbox and AI accounts.

Optional hosted connector

ReplyPort MCP service

ReplyPort separately operates an optional hosted MCP service on Cloudflare. When a user authorizes a ChatGPT, Claude or other compatible MCP client, the service obtains a Dropbox App Folder authorization for that client. The Dropbox app is scoped to its App Folder and requests basic account information plus file metadata, content read and content write access.

The Worker reads approved mirrored message metadata, snippets and bodies from the user’s ReplyPort Dropbox App Folder to answer authorized requests. It can write draft request records and read matching local receipts. Requested message content is returned to the chosen AI host, which processes it under its own terms and settings. The service does not connect to Outlook and does not keep a second mailbox mirror. The ReplyPort Windows application on the user’s PC remains the only Outlook executor and creates any native unsent draft.

Hosted credentials and logs

Dropbox access and refresh credentials for each connector are stored in Cloudflare Workers KV as OAuth grant properties encrypted by the OAuth provider with AES-GCM. The MCP bearer token and Dropbox token are separate. Worker observability is disabled, and the ReplyPort application does not log MCP request bodies or email content. Cloudflare may separately process network, security and service metadata as part of hosting. The exact platform-level logs, telemetry and retention periods for this Worker have not been confirmed and must be reviewed before launch.

Services you choose

When third parties may process information

The ReplyPort Windows application does not upload mirrored Outlook email to a publisher-operated mail or AI server. It places authorized copies in the user’s Dropbox account, as described above. A separately authorized AI connector or hosted integration may access or process the records the user makes available to it, according to that connection’s permissions and terms. The Windows app contains no ReplyPort analytics or telemetry. The optional ReplyPort-hosted MCP service is separate: it reads approved copies from Dropbox and returns requested content to the selected AI host.

Website promotion measurement

The public ReplyPort website may use limited advertising and campaign measurement to understand whether a visitor reached the site from a ReplyPort promotion and whether they chose the Microsoft Store link. When enabled, this may include the OpenAI Ads Measurement Pixel, the Google Ads conversion tag, first-party attribution cookies, URL campaign parameters and a Microsoft Store campaign ID. This website measurement is separate from the Windows app and does not provide advertising systems with Outlook message content or ReplyPort's local mailbox data.

Information may nevertheless be processed by the services the user uses with ReplyPort:

  • Microsoft and the user's mailbox provider continue to process Outlook mailbox data under the account and service the user already uses. ReplyPort's local Outlook integration does not replace those arrangements.
  • Dropbox processes the files ReplyPort places in its dedicated App Folder, which Dropbox Desktop synchronizes through the user’s account. Dropbox’s API also processes account identity and small verification files during authorization and setup.
  • Cloudflare hosts the optional ReplyPort MCP service and its encrypted OAuth grant store. The Worker processes authorized Dropbox file reads and writes in response to MCP requests. Cloudflare’s platform-level operational processing and retention are subject to Cloudflare’s terms; ReplyPort has not established the exact platform log-retention periods for this Worker.
  • An external AI service, AI-enabled tool or separately authorized integration may process ReplyPort data that the user chooses to make available for searching, analysis or drafting. Its Dropbox permissions can differ from ReplyPort’s App Folder-only authorization.

Each selected service operates under its own terms and privacy policy. Users should review those terms and only make mailbox information available to a service they are permitted and willing to use.

Generative AI

AI-assisted output requires review

ReplyPort does not provide a generative-AI model. The user chooses the AI service. If the user connects through the hosted MCP service, the service returns requested mail content to that AI host; the AI host then processes it under its own terms, settings and retention practices.

Generative-AI output can be inaccurate, incomplete, biased or inappropriate. The user must review and, where necessary, edit every draft before deciding whether to send it.

To report inappropriate AI-generated content associated with ReplyPort, email sergei.v.alexeev@gmail.com. Please do not include confidential email content unless it is necessary to investigate the report.

Retention and controls

Your choices

The Windows application defaults to copying recent messages from the previous 90 days, but a user can locally select a 12- or 24-month history window for an enabled mailbox. Mirror snapshots and their optional attachment copies expire according to the configured retention floor and retained history high-water mark; switching to a shorter history window does not immediately delete older copies. Files needed for pending work or safe recovery can remain longer. Disposable search requests and results normally expire after seven days.

Draft request and receipt records in Dropbox can remain after a request is processed; the Windows app does not apply a general automatic expiry to all draft records. In the hosted service, request-ID claim metadata is separate from message content: pending or deferred claims remain active until the local worker reports a terminal receipt, and a verified terminal claim is retained for 90 days. The Durable Object cap is 2,048 claims per Dropbox principal; a new request is refused if active or recent claims fill that cap. A staged file, when used, expires at its recorded receipt expiry (24 hours by default) or on completion.

Active Dropbox OAuth grants remain while authorized. Disconnecting or revoking a connection invalidates the relevant authorization; provider-side removal of encrypted KV values is best effort and no fixed cleanup time is established. Worker application request-body logging is disabled. Cloudflare may retain platform-level service or security metadata under its own practices; ReplyPort has not verified a specific retention period.

The user controls ReplyPort and can:

  • stop copying selected mail or stop using the dedicated ReplyPort App Folder in Dropbox;
  • choose, for each mailbox, whether email attachments are copied, and turn this off at any time, which removes the attachment copies;
  • disable ReplyPort to stop its background processing;
  • choose whether to use any external AI service or AI-enabled tool;
  • disconnect a ChatGPT, Claude or other MCP client, and separately revoke ReplyPort’s Dropbox access through Dropbox account settings;
  • delete ReplyPort-managed data in the App Folder using Remove ReplyPort… → Delete ReplyPort data too in Control Centre, or manage those files directly in Dropbox; and
  • uninstall the Windows application; use ReplyPort’s removal options separately when local configuration or Dropbox data should also be cleared.

Disconnecting a host does not necessarily revoke the linked Dropbox grant or delete files in the App Folder. Removing Dropbox authorization and deleting Dropbox files are separate actions. Revocation does not delete Outlook drafts. Disabling or uninstalling ReplyPort does not delete, move or otherwise change messages in Outlook. Uninstalling the app alone does not delete files in the Dropbox App Folder; removing those copies requires a separate action. ReplyPort’s removal process protects unrecognized content rather than deleting it as application data. Deleting synchronized files also affects the user’s Dropbox online and other synchronized devices. The publisher does not promise immediate erasure of revoked OAuth grant records or Cloudflare platform logs.
